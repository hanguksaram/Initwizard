# Словарь для разговора с оператором

Когда впервые произносишь слово из левого столбца — сразу объясни его словами из правого. Не используй внутренние слова платформы без объяснения. Если оператор спрашивает о термине, которого здесь нет, и ты не знаешь точного ответа — так и скажи.

| Слово | Как объяснить оператору |
|---|---|
| Gina | Платформа, на которой работают AI-агенты проекта. Принимает просьбы людей, раздаёт работу агентам, следит за ходом. |
| Инстанс (анклав) | Отдельная установка Gina для одного проекта. Живёт в Kubernetes, в своём пространстве (его имя оператор называет на шаге 1). |
| Методология | Набор текстов, по которым работают агенты: кто они, что умеют, в каком порядке идёт работа. Хранится в Git. |
| Агент | Роль с собственной инструкцией: аналитик, разработчик, ревьюер. Один и тот же AI, но с разными задачами и правами. |
| Навык | Справочный текст, который агент получает под задачу: как ходить в репозиторий, как оформить merge request, как устроен проект. |
| Базовый навык | Навык из пакета, одинаковый для любого проекта: порядок работы, общение с людьми, работа с GitLab и Jira. |
| Навык проекта | Навык, который мастер составляет на шаге 3 по ответам оператора и исследованиям: паспорт проекта, правила кода, карта интерфейса. |
| Признак | Отметка в журнале мастера «у проекта это есть»: GitLab через прокси, Jira через прокси, составлен навык правил кода, составлен навык интерфейса. От признаков зависит, какие элементы методологии ставятся. |
| Исследование | Необязательное чтение источников проекта на шаге 3 (репозитории, сборки, правила кода, среда исполнения, трекер, интерфейс). Ничего не меняет. |
| Правила роли платформы | Общие правила для служебных ролей Gina. «Планировщик» решает, какой агент делает следующий шаг. «Исполнитель» — общее имя для любого агента в работе. «Диспетчер входящих» решает, к какой работе отнести новую просьбу. «Завершение и напоминания» решает, когда работа закончена и кому напомнить. Правила каждой роли на инстансе существуют в одном экземпляре. |
| Дело | Одна единица работы от просьбы до результата: одна задача из трекера или одна просьба из чата. |
| Заход | Один сеанс работы одного агента внутри дела. Дело обычно состоит из нескольких заходов разных агентов. |
| Входящее | Новое сообщение для Gina: просьба человека, ответ на вопрос агента, событие («сборка закончилась»). |
| Источник промптов | Настройка инстанса: из какого репозитория и какой ветки он берёт методологию. Инстанс читает ровно одну ветку. |
| Ветка POC | Отдельная ветка в репозитории методологии, которую создаёт мастер. В неё ставится вся новая методология. Пока инстанс на неё не переключён, она ни на что не влияет. |
| Предпросмотр | Проверка без применения: инстанс читает ветку, говорит, нет ли в ней ошибок и что изменилось бы, но ничего не меняет. |
| Переключение источника | Момент, когда инстанс начинает читать ветку POC. С этого момента агенты работают по новой методологии, а агенты и навыки, которых в ветке нет, выключаются. |
| Подключение (адаптер) | Запись на инстансе о внешней системе: её адрес и ссылка на ключ. После него агенты ходят в систему через Gina по внутреннему адресу. Создаётся на шаге 2. |
| Хранилище секретов инстанса | Место на инстансе, где лежат ключи внешних систем. Агенты и мастер значений оттуда не получают; ключ подставляет сама Gina в момент запроса. |
| Короткий адрес | Адрес подключения внутри инстанса, например `/gitlab`: по нему агент обращается к внешней системе. У типа системы один общий короткий адрес; второму подключению того же типа задаётся свой. |
| Техническая учётная запись | Учётная запись во внешней системе, заведённая для агентов, а не для человека. Её ключ кладётся в подключение. |
| Прокси Gina | Агенты ходят во внешние системы (хостинг кода, трекер) не напрямую, а через Gina: она сама подставляет учётные данные, поэтому агентам токены не нужны. Какие системы подключены — показывает шаг 3. |
| Регламент | Расписание на инстансе: действие, которое Gina выполняет сама через заданный интервал. В этой установке он один и ставится, только если код проекта лежит в GitLab, подключённом к инстансу. |
| Регламент побудки по сборке | Единственный регламент установки; на инстансе называется «СТОРОЖ СБОРКИ». Раз в минуту проверяет, закончилась ли сборка, которую ждёт агент, и будит его дело. Модель не вызывает. |
| Сторож инстанса | Программа на машине агента-оператора (`watcher/watch.py`). По расписанию снимает состояние инстанса и сообщает о сбоях. К регламенту побудки по сборке отношения не имеет. |
| Под исполнителя (jcode) | Контейнер в Kubernetes, внутри которого агенты выполняют команды. Он общий для всех агентов и небольшой. |
| Пайплайн, CI | Автоматическая сборка и проверка кода после изменения. |
| Стенд | Развёрнутый экземпляр продукта, на котором можно посмотреть его в работе. |
| Токен владельца | Ключ с полными правами на инстанс Gina. Им можно и читать настройки, и менять их. |
