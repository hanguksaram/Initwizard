# Шаг 5. Итоговая проверка

`python3 scripts/wizard_state.py step 5 start`

**Скажи оператору (своими словами):** «Проверю всё установленное одним прогоном: доступы, контейнеры инстанса, каналы, которыми агенты ходят во внешние системы, какую ветку читает инстанс и попали ли в него наши тексты, регламент и сторожа».

```bash
python3 watcher/watch.py --no-notify      # чтобы у сторожа был свежий запуск
python3 scripts/healthcheck.py
```

Статусы: `OK` — работает; `WARN` — работает с оговоркой или **не проверено**; `MISS` — не ставилось, не задано по решению оператора либо к этому проекту не применимо; `FAIL` — должно работать, но не работает.

Покажи таблицу и строку «Итог». Разбери каждую строку, кроме `OK`, — причину бери из последнего столбца, не придумывай свою:

| Группа | Что значит не-`OK` | Что делать |
|---|---|---|
| доступы | перестал работать доступ из шага 1 либо необязательный не задан | `FAIL` — вернуться к шагу 1; `MISS` — напомнить решение оператора |
| поды | контейнер инстанса не готов | это сбой инстанса, не установки: сообщи оператору, посмотри события и журнал пода; сам не перезапускай |
| прокси Gina: `FAIL` | агенты Gina не смогут ходить в систему, названную в строке | это настройка подключений инстанса — задача оператора |
| прокси Gina: `MISS` «не применимо» | признак выключен на шаге 2: такой системы у проекта нет или к инстансу она не подключена | напомни, что из-за этого агенты не могут делать |
| прокси Gina: `WARN` «не проверены» | нет права выполнять команды в поде | скажи прямо: «не проверено» |
| прокси Gina / каналы общения: `WARN` | к инстансу не подключён ни один канал разговора | просьбы из чата до агентов не дойдут; подключение — задача оператора |
| инстанс / читает ветку POC: `MISS` | инстанс не переключён | методология лежит в ветке и не действует; напомни решение из шага 3.4 |
| инстанс: `FAIL` | ветка POC не применилась | `python3 scripts/source_switch.py show`; предложи оператору возврат прежнего источника |
| методология: `MISS` «не применимо» | элемент зависит от признака, выключенного на шаге 2 | назови признак и основание из журнала |
| методология: `MISS` «не ставилось» / «пропущено» | накат до элемента не дошёл либо оператор пропустил | напомни, на чём остановились и почему |
| методология: `WARN` | merge request открыт и не влит; либо сверка не завершена | `mr_rollout.py verify <номер>` |
| методология: `FAIL` | влито, но не совпадает с пакетом или инстанс не применил | `mr_rollout.py verify <номер>`; не помогло — сказать оператору, что напечатано |
| методология / регламент: `MISS` | создан, но выключен, либо пропущен | напомни решение; последствие — после отправки кода агент сам не узнает, чем кончилась сборка |
| сторож инстанса / расписание: `MISS` | расписание ещё не установлено | это ожидаемо до шага 7 |
| сторож инстанса / расписание: `WARN` | установлено, но ещё не срабатывало | проверить после первого срока |
| стенды продукта: `WARN` | адрес интерфейса не отвечает или отвечает ошибкой | справочно: назови код ответа; причину не додумывай |

Не подгоняй результат. `FAIL`, который не удалось устранить, остаётся в итоге с объяснением.

- Нет `FAIL` — `python3 scripts/wizard_state.py step 5 done`.
- `FAIL` остались — `step 5 partial "<какие>"`; в итоге шага 6 заголовок будет «завершена частично».
